Task 4 – Week 5: Extend the work from individual pre-layout SRAM blocks to physical verification and post-layout characterization of an OpenRAM-generated SRAM macro. Generate a small 2-word × 16-bit, single-port SKY130 SRAM using OpenRAM and retain the configuration, commands, logs and generated GDS, LEF, Liberty, Verilog and SPICE files. Use ChatGPT, Codex or another AI tool to audit these outputs for pin, bus-width, address-width, power-net and timing-model consistency and to identify whether DRC, LVS, PEX or transistor-level characterization were disabled. Generate a self-checking regression testbench covering write-0, write-1, alternating data patterns, reads from multiple addresses, back-to-back operations, disabled cycles and data retention. Enable and run Magic DRC, Netgen LVS and parasitic extraction; use AI to analyse and classify failures, but verify every fix through the EDA tools. Simulate the extracted SRAM using ngspice at representative TT, FF and SS corners and measure read access time, write time, leakage and read/write energy. Compare measured results against the OpenRAM-generated Liberty values and automatically flag negative, missing or significantly inconsistent results. Extend the existing hold-SNM workflow to calculate read and write SNM for the 6T cell and compare all three stability margins. Submit all prompts, scripts, configuration files, testbenches, generated views, DRC/LVS/PEX logs, waveforms, measurements, comparison tables, errors, fixes and conclusions through GitHub. Use the small SRAM for this one-week validation; applying the verified flow to the complete 4 KB SRAM can be the following task.
